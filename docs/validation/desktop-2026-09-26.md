# Desktop companion validation — 2026-09-26

Scope: the Linux x64 `0.1.0-alpha.1` source preview in `apps/desktop`, using the
SDK provider onboarding from `d4bfda8` and empty-host/activity support from
`9ba157a`. This is separate from the published registry SDK 0.1.0 and is not a
public desktop release. See [installation and lifecycle](../desktop.md).

## Backend and isolation checks

Seven desktop tests passed against the actual SDK, covering:

- An empty private host, stable endpoint and credentials after restart, saved
  startup preference, scoped invitations, management rejection and revocation.
- Durable remote profiles, explicit host selection, remote management grants,
  private credential files and forgetting a profile without stopping its host.
- The existing Usagestat read contract, native metric records, missing values,
  write-only service credentials and credential removal when changing endpoints.
- A synthetic streamed request that remains active during metadata refresh;
  ordinary shutdown refuses to interrupt it and explicit interruption closes it.
- Main-frame-only IPC, bounded requests and supported operation validation.
- A restricted bundled-asset protocol and documentation-link allowlist.
- Distribution permissions that work across users without following symlinks or
  changing private profile files.

The real locally installed `usagestatd` also passed an isolated `--no-poll` check
of `GET /v1/providers` and `GET /v1/usage`. No provider calls were made. Its native
quota/cost records are read through usage metrics; the desktop does not assume
that a separate `/v1/limits` route exists. Existing Usagestat services, ingestion
bindings and application hosts were not modified.

## Native and visual checks

The native smoke test launches Electron 44.4.5, loads the actual renderer, passes
through its narrow IPC bridge to bundled Node 24.21.0, and configures a synthetic
provider through the real SDK. It checks context isolation, renderer sandboxing,
absence of renderer Node APIs and working provider management. It passed on
Fedora 44, both in development and from the portable Linux artifact.

The portable artifact also passed as a separate non-root user in a Debian
Bookworm container under Xvfb, with networking disabled and the Electron renderer
sandbox enabled. This found a restrictive artifact-directory permission problem;
the packaging hook now normalizes only public distribution files, with a
regression test. The container uses its own setuid sandbox helper and Docker
`--init`; production code does not use `--no-sandbox`.

T3's collaborative browser exercised the same renderer and controller through a
development-only loopback preview at desktop and 390 × 844 viewports:

- Provider setup/catalog controls, the add-provider picker and a restricted
  application profile with one provider and no management controls.
- Clearly synthetic Usagestat metrics, source/freshness labels and missing data.
- Creation and exchange of a one-use invitation, selection of its scoped host
  profile, local host stop/start with endpoint restoration, and grant revocation.
- No horizontal page overflow; no persistent browser token/invitation storage.

The preview's provider/usage fixtures are synthetic and are not shipped as user
configuration. The fixture stream used a loopback peer; no model inference was
sent to a provider. Test watchdogs do not introduce production run timeouts.

## CI and coverage limits

The SDK workflow adds a **Linux desktop companion** job on Prometheus. It runs
the desktop tests, builds the archive, repeats the offline native container
check and retains the archive as a seven-day CI artifact. The issue closure
records the exact passing commit and workflow run.

The first full CI run also caught the SDK release guard rejecting the desktop's
tracked `.npmrc` filename. Dependency installation now passes `--install-links`
explicitly, with that file removed; the private-file release guard is unchanged.

Windows, macOS, Linux ARM, signed installers, automatic updates, NAT relays and
native interactive provider sign-in are outside this qualification. Existing
native sessions and explicit API credentials are supported; owned browser/device
sign-in remains [#50](https://github.com/agenticdriver/agenticdriver/issues/50).
Catalog availability does not imply live model qualification or execution grants.
