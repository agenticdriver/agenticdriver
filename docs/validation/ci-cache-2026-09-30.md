# Private Prometheus CI cache recovery — 2026-09-30

Tracking: [AD-084 / #81](https://github.com/agenticdriver/agenticdriver/issues/81).
Implementation: [`9c60001`](https://github.com/agenticdriver/agenticdriver/commit/9c60001).

The managed-runtime source checks reached the existing 8 GiB storage guard with
7.7 GiB free. Normal cleanup retained 2 GB of unused private BuildKit cache, so
documentation and candidate packaging stopped before compilation. The guard
correctly refused the build; it was not a test failure or a provider failure.

The policy now checks free space after normal cleanup. When less than 8 GiB
remains, it reclaims all unused BuildKit records in the dedicated SDK daemon's
default builder and checks again. It retains the guard when that cleanup is
insufficient. It never removes containers, images, volumes, application data,
native credentials or another runner's cache.

Exact repository, branch, runner name, workflow event and private daemon checks
precede cleanup. Overridden Docker contexts, TLS settings and builders are
rejected. Nine policy checks cover scope rejection, conditional reclamation and
the retained guard. Those pure subprocess/disk-policy checks are distinct from
the actual recovery below and do not simulate provider execution.

## Actual recovery and candidate CI

The helper ran on the idle dedicated Prometheus SDK runner and restored 8.8 GiB
free. The same managed-runtime source then passed all seven checks on
[run 36654580365, attempt 3](https://github.com/agenticdriver/agenticdriver/actions/runs/36654580365/attempts/3).
Earlier failed attempts remain visible.

The RC.3 candidate included the new policy and passed all seven checks on
[run 36656551940](https://github.com/agenticdriver/agenticdriver/actions/runs/36656551940).
Its documentation job actually reached the conditional cleanup:

```text
2026-09-30T01:55:33.5498215Z Low storage after normal cleanup; reclaiming unused private SDK build cache
2026-09-30T01:55:34.7093957Z Private CI build-cache maintenance complete; 8.8 GiB free on /work
```

Candidate packaging subsequently passed its storage preflight and exact-source
build/install checks. This is observed recovery on the authorized private runner;
it is not a promise that cache pruning can resolve every future capacity issue.
The published desktop/SDK archives and existing application services were
preserved. No free-space requirement was reduced.
