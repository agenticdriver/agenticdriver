# Codex native compatibility — 2026-09-25

These checks use development source after the published SDK 0.1.0 release.
The tested binary is **Codex CLI 0.157.0 on Linux x64**. Its SHA-256 is
`1a822376d4634ac32dddc030e5117c63359f7f8cd4b1b64382c68190287d0258`.
This does not establish compatibility for other CLI versions or operating systems.

## Reproduce the native fixture

Install Linux bubblewrap, Python 3.10+ and Node.js, then build the SDK. Supply the
absolute path to the official native ELF executable. For an npm installation,
this is the `bin/codex` executable inside the platform-specific
`@openai/codex-linux-*` package, not the JavaScript `codex` launcher.

```sh
npm ci
npm run test:codex-native -- \
  --binary /absolute/path/to/native/bin/codex \
  --receipt /tmp/codex-native-receipt.json
```

The runner hides the real home directory and `/tmp`, disables external
networking in a fresh namespace, and creates two synthetic API-key account
directories plus a synthetic managed-session account. Fake credentials belong
only to loopback Responses and OAuth fixtures. The wrapper sets those endpoints,
the fixture credential store, and telemetry options; execution restrictions
come from the real SDK adapter.

The native fixture verifies:

- The selected account's synthetic credential reaches the local endpoint; an
  ambient API key does not replace it.
- The requested model and `reasoningEffort: "medium"` reach the provider.
- Text, item-level progress and reported input/output/cached usage normalize
  through the SDK; `textStreaming` remains `false`.
- HTTP 401, 429 and a recognized missing-model 404 become fixed public error
  codes. Unknown 503 diagnostics remain `CLI_FAILED`. Private error bodies and
  endpoint URLs do not appear in the SDK error.
- Missing sign-in is reported by native discovery. A synthetic expired access
  token refreshes through the native managed-session flow; updated credentials
  and refresh time are saved by Codex before the successful request.
- Expired, reused and revoked refresh tokens produce `CLI_AUTH_REQUIRED`, with
  no SDK retry and no changes to the synthetic stored credentials.
- Cancellation closes the native request, leaves no native child processes,
  and does not retry the request.
- No tools are advertised, and seeded hook/MCP processes do not start.
- User configuration and parent workspace instructions are absent from the
  request. Global instructions and skill descriptions are measured separately.

The receipt records the binary and built adapter hashes, source revision/dirty
state, and individual results. All model responses and usage numbers are
synthetic. Fixture watchdogs bound test infrastructure only; SDK run and
inactivity timeouts remain disabled by default.

## Managed-session expiry and refresh

All fourteen native fixture checks passed on the binary above. These include
actual native OAuth recovery, beyond the earlier API-key HTTP 401 fixture.
The fixture supplies a deliberately expired synthetic JWT and mock refresh
credentials. It uses the native `CODEX_REFRESH_TOKEN_URL_OVERRIDE` test seam
documented in the pinned [upstream authentication implementation](https://github.com/openai/codex/blob/rust-v0.157.0/codex-rs/login/src/auth/manager.rs)
and [upstream refresh tests](https://github.com/openai/codex/blob/rust-v0.157.0/codex-rs/login/tests/suite/auth_refresh.rs).
The SDK neither forwards that variable from the host environment nor manages
the native credential store; only the isolated test wrapper sets it.

Successful recovery made one refresh call and one successful Responses request.
Each permanent refresh failure made four native refresh calls and two rejected
Responses requests during native startup/auth recovery, all within one native
execution. Those are native internal attempts, not SDK run retries. The fixture
records those counts and verifies the SDK never starts a second execution.
Raw refresh diagnostics, synthetic credentials and URLs stay out of public SDK
errors. No real credentials are read, modified, copied or invalidated, and no
external authentication server or model is contacted by these tests.

## Native context limitation

On 0.157.0, the account directory's global `AGENTS.md` and descriptions from the
user's global skill catalog still reach the model despite `--ignore-user-config`,
`project_doc_max_bytes=0`, a temporary workspace and disabled native tools.
This is observed prompt inheritance, not evidence of tool execution.

The CLI documents `--ignore-user-config` as skipping its user `config.toml`;
global instruction and skill discovery have separate rules. The adapter also
passes `--ignore-rules` and `--strict-config` and checks for these flags before
submitting a prompt. Missing required flags produce `CLI_UPGRADE_REQUIRED`.
See the official [CLI command reference](https://learn.chatgpt.com/docs/developer-commands),
[instruction discovery](https://learn.chatgpt.com/docs/agent-configuration/agents-md),
[skill discovery](https://learn.chatgpt.com/docs/build-skills), and
[reasoning configuration](https://learn.chatgpt.com/docs/config-file/config-reference).

For application-only context, run the native CLI under a dedicated OS user or
container with a clean home and sign in normally there. Selecting a separate
`accountDirectory` alone does not hide the OS user's global skills. The SDK
does not remove user files, copy credentials or claim an OS isolation boundary.

## Live qualification

The user selected the existing local Codex sign-in, `gpt-6-luna`, and medium
reasoning. On 2026-09-25, the actual SDK adapter completed a live request and
returned the requested `AGENTICDRIVER_CODEX_OK` text. Its events were
`run.started`, `step.started`, `text.delta`, `usage.reported`, and `run.completed`.
The CLI reported 13,432 input tokens, 12 output tokens, and 6,912 cached input
tokens. This is reported token usage, not a subscription charge or API-price
estimate. No credential contents were inspected or copied.

A separate live cancellation check used the same selection, cancelled two
seconds after the native `exec` process started, and returned `CANCELLED`.
The owned wrapper and native process were both reaped. The check did not receive
model output or usage before cancellation and does not establish when remote
generation stopped or whether that cancelled request consumed quota.

These results establish the tested account/model's live text route and local
cancellation. Missing and expired-session handling and successful native refresh
are qualified separately by the isolated managed-session fixtures above. The
user's real account was not forced to expire, and real authorization-server
refresh availability is not certified. Other CLI versions, OSes, model choices
and the three applications' end-to-end flows require their own evidence.
